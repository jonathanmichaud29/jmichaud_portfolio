# Environment Variables and Secrets

Part 9 of the series. Repo structure, base images, Compose topology, Dev Container, volumes, and UID/GID mapping are all done. Now we answer: **where do credentials live, who generates them, and what blocks a bad value from reaching a container?**

---

## Why a single `.env` breaks down

One `.env` + one `.env.example` works until someone commits `.env` by accident, copies a staging credential locally, or adds a variable without documenting it. The failure is always silent. The fix is a deliberate taxonomy, one enforced file format, and tooling that generates what it can and blocks what isn't ready.

---

## Taxonomy of values

Four categories with different security requirements:

| Category                | Examples                               | Committed?                 | Generated?                  |
| ----------------------- | -------------------------------------- | -------------------------- | --------------------------- |
| Infrastructure          | `UID`, `GID`, `COMPOSE_PROJECT_NAME`   | As `REPLACE_ME` in example | Yes — `make init`           |
| App config (non-secret) | `APP_ENV`, `LOG_LEVEL`, `API_BASE_URL` | Safe defaults directly     | No                          |
| Generated secrets       | `DB_PASSWORD`, `APP_KEY`               | As `REPLACE_ME` in example | Yes — `make init`           |
| Third-party credentials | `STRIPE_SECRET_KEY`, external API keys | As `REPLACE_ME` in example | No — manual, with docs link |

Key distinction: anything the project controls (DB password, app key) is auto-generated at init — developers should never type these. Anything requiring an external account must be documented and filled in manually.

---

## File structure

Two files only:

```
.env.example    # committed — the contract for what variables exist
.env            # gitignored — generated by make init, never committed
```

`.env.example` is the single source of truth. If a variable isn't there, it doesn't exist from an onboarding perspective. `.env` appearing in a PR is a process failure, not a developer failure — `.gitignore` is the first line of defence.

---

## The sentinel pattern

Every variable requiring action uses `REPLACE_ME` as its placeholder — one pattern, `grep`-able, unambiguous. Empty strings are avoided because some drivers (e.g., DB drivers) silently accept them as valid.

```bash
# === Infrastructure (generated by make init) ===
UID=REPLACE_ME
GID=REPLACE_ME
COMPOSE_PROJECT_NAME=my-project

# === Application config (safe defaults — no action needed) ===
APP_ENV=local
LOG_LEVEL=debug
API_BASE_URL=http://api:8080

# === Generated secrets (make init replaces these automatically) ===
DB_PASSWORD=REPLACE_ME
APP_KEY=REPLACE_ME

# === Third-party credentials (manual — see docs/credentials.md) ===
STRIPE_SECRET_KEY=REPLACE_ME
```

## The Makefile

Three public targets, two internal ones (prefixed with `_` by convention):

```
make init       → one-time bootstrap: copy, generate, inform
make build      → runs _preflight, then docker compose build
make up         → runs _preflight, then docker compose up
```

### `_check-env` — inform, never block

Runs at the end of `make init`. Lists what still needs manual setup. Never exits with a non-zero code.

```makefile
_check-env:
	@MISSING=$$(grep -E "^[^#].*=REPLACE_ME" .env | cut -d= -f1); \
	if [ -n "$$MISSING" ]; then \
		echo ""; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		echo "⚠️  Action required — manual credentials needed"; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		echo ""; \
		echo "The following variables still require manual setup:"; \
		echo ""; \
		for var in $$MISSING; do echo "  • $$var"; done; \
		echo ""; \
		echo "📖 docs/credentials.md"; \
		echo "   https://github.com/your-org/your-repo/blob/main/docs/credentials.md"; \
		echo ""; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		echo ""; \
	else \
		echo "✅ .env is fully configured — run: make up"; \
	fi
```

### `_preflight` — enforce, hard block

Runs before every `make build` and `make up`. Exits non-zero if `.env` is missing or any `REPLACE_ME` values remain, preventing Docker from ever seeing an unconfigured credential.

```makefile
_preflight:
	@test -f .env || { \
		echo "🚫 .env not found — run: make init"; \
		exit 1; \
	}
	@MISSING=$$(grep -E "^[^#].*=REPLACE_ME" .env | cut -d= -f1); \
	if [ -n "$$MISSING" ]; then \
		echo ""; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		echo "🚫 Build blocked — credentials not configured"; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		echo ""; \
		echo "The following variables in .env still contain REPLACE_ME:"; \
		echo ""; \
		for var in $$MISSING; do echo "  • $$var"; done; \
		echo ""; \
		echo "📖 docs/credentials.md"; \
		echo "   https://github.com/your-org/your-repo/blob/main/docs/credentials.md"; \
		echo ""; \
		echo "━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━"; \
		exit 1; \
	fi
```

### `init` — the bootstrap sequence

```makefile
init:
	@test -f .env && { echo "⚠️  .env already exists. Delete it manually to reinitialize."; exit 1; } || true
	@cp .env.example .env
	@# Infrastructure
	@perl -i -pe "s/^UID=REPLACE_ME/UID=$(shell id -u)/" .env
	@perl -i -pe "s/^GID=REPLACE_ME/GID=$(shell id -g)/" .env
	@# Generated secrets
	@perl -i -pe "s/^DB_PASSWORD=REPLACE_ME/DB_PASSWORD=$(shell openssl rand -base64 16 | tr -dc 'a-zA-Z0-9' | head -c 20)/" .env
	@perl -i -pe "s/^APP_KEY=REPLACE_ME/APP_KEY=$(shell openssl rand -hex 32)/" .env
	@$(MAKE) _check-env
```

`make init` is intentionally one-time — if `.env` already exists, it exits immediately. Accidental re-runs should not silently regenerate passwords and break running containers.

### `.PHONY` declaration

```makefile
.PHONY: init build up _preflight _check-env
```

All non-file targets — public and internal — must be listed here. `.PHONY` is a Make correctness mechanism, not access control.

---

## Why `perl -i` over `sed -i`

`sed -i` is not portable: macOS needs `sed -i ''`, GNU/Linux needs `sed -i`. Since the Makefile runs on the host across macOS, Linux, and WSL2, a `sed -i` call silently produces wrong results on at least one platform. `perl -i` behaves identically on all three, with no extra installation required.

---

## Secret generation

```makefile
# High-entropy hex — app signing keys, session secrets
APP_KEY=$(shell openssl rand -hex 32)

# Alphanumeric — database passwords, broker credentials
DB_PASSWORD=$(shell openssl rand -base64 16 | tr -dc 'a-zA-Z0-9' | head -c 20)
```

`openssl` is available everywhere without installation. The base64-then-filter approach strips shell-unsafe characters (`+`, `/`, `=`) that break connection strings, without pulling in extra dependencies like `pwgen`.

---

## Third-party credentials

These cannot be generated. `make init` leaves them as `REPLACE_ME`, `_check-env` lists them with a link to `docs/credentials.md`, and `_preflight` hard-blocks the build until they're filled in. Enforcement is global — every variable in `.env.example` is required by something in the stack.

---

## CI

GitHub Actions injects secrets directly as `env:` variables in workflow steps — no `.env` file is written to the runner. Variable names must exactly match what's declared in `.env.example`. Adding a variable to `.env.example` requires adding the corresponding secret in the GitHub repository before the next CI run.

## Developer onboarding

```
git clone <repo>
cd my-project
make init          # copies .env, generates secrets, warns on manual items
                   # → follow docs/credentials.md for third-party keys
# fill in remaining REPLACE_ME values in .env
make up            # _preflight validates — hard blocks if anything remains
```

Three commands from clone to running containers. `_check-env` tells the developer exactly what still needs doing and where to go.

---

## Artifacts produced

- `.env.example` — committed, structured with comment sections, `REPLACE_ME` sentinels
- `.env` — gitignored, generated by `make init`, never committed
- `Makefile` — `init`, `build`, `up`, `_preflight`, `_check-env` targets
- `docs/credentials.md` — manual credential setup instructions, linked from all warning messages
